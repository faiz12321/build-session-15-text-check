How to check a text file for line endings and stray spaces with Python

Short answer

Two text files can look the same on screen and still differ in invisible ways. This lesson builds a small read-only Python tool that reads a file as raw bytes and reports how many lines end the Windows way and the Unix way, lone carriage returns, lines with a tab, lines that end with a space or tab, a last line with no line ending, NUL bytes and text that is not valid UTF-8. It shows how many problems it found and the first five line numbers of each kind.

Follow along and build it step by step. You add each file yourself, run each command, and see the real recorded result.

Common mistakes

  1. Trusting what the screen shows. Windows and Unix line endings look the same in most places you read a file, but the bytes differ. The tool reads the raw bytes.
  2. Using text mode to inspect line endings. The Python documentation says text mode can translate line endings when it reads a file. The first version in this lesson reads that way and cannot tell the two files apart.
  3. Calling Windows line endings wrong. One kind of line ending throughout is not reported as a problem. The tool reports a file that mixes kinds.
  4. Treating a pass as proof the file is right. These checks look at bytes and spacing, not meaning. A file can pass and still hold wrong text.

Frequently asked questions

How do I check a text file for line endings with Python?

Open the file in binary mode so nothing is translated, then count the carriage return plus line feed pairs and the lone line feeds. This lesson builds a small tool that does that and more.

Will this change my file?

No. The tool only reads the file. A test checks that one small test file has the same bytes and the same modified time before and after a run. That is the only evidence for this claim.

Why does the first version give the same answer for both files?

It reads the file in text mode. The Python documentation says that in the default mode, lines ending in a line feed, a carriage return or both are translated to a line feed when read. The count of lines comes out the same.

Does it list every problem?

It counts every problem of the kinds it checks, but shows only the first five line numbers of each kind.

Is a tab a problem?

The tool reports tabs as a note only. Whether tabs are acceptable depends on the program that reads the file.

Does valid UTF-8 mean the text is right?

No. The tool only checks that the bytes can be read as UTF-8. Text in another encoding can happen to look valid.
